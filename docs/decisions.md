# 결정 로그

설계 초안 v0.6 기준. 출처는 [`design-map.html`](design-map.html)의 각 절이며, 아래 날짜는 모두 결정이 문서에 반영된 날짜입니다.

---

- **2026-08-17 · 앱 이름 = 더잔잔 / The Janjan** (확정)
  "더(the) 잔잔". 물결이 잔잔하다는 뜻. 투약 앱임이 이름에 드러나지 않아 잠금화면에 떠도 명상·일기 앱처럼 보인다. 스토어 영문명 `Janjan`, 도메인 후보 `thejanjan.app`. 상표(KIPRIS 09·42·44류)는 로고 결합상표로 출원 예정. 검토 후 뺀 이름: 약속 / 필로그 / 도즈.

- **2026-08-17 · 플랫폼은 iOS + watchOS 전용** (확정)
  안드로이드 계획 없음. iOS 17+ / watchOS 10+. 1차 시장 한국, 한·영 2개 언어.

- **2026-08-17 · Capacitor(웹) 대신 SwiftUI 네이티브** (확정)
  이전 앱(러비티) 교훈. 워치 앱·알림 액션·컴플리케이션은 네이티브가 아니면 사실상 불가. 코드량은 늘지만 심사 예외 케이스가 줄어든다.

- **2026-08-17 · 로그인 없음 · 서버 없음 · 광고 없음** (확정)
  SwiftData + CloudKit **private** DB만 사용. 개발자가 데이터를 볼 수 없는 구조 → Privacy Label "데이터를 수집하지 않음", 건강정보 광고 금지(5.1.3) 회피, Sign in with Apple·계정 삭제·client secret 갱신 이슈 원천 제거. 분석·크래시 서드파티 SDK도 v1엔 없음.

- **2026-08-17 · 수익화는 Pro 구독** (확정)
  구독 그룹 1개 · 상품 2개(`pro_monthly`, `pro_yearly`), entitlement 이름은 `pro` 하나. **월 ₩2,900 / 연 ₩19,900**, 7일 무료 체험은 **연간에만**. 연간이 기본 선택("월 ₩1,658 꼴" 표기). 가격은 출시 3개월 지표로 재조정.

- **2026-08-17 · 무료 / Pro 경계** (확정)
  무료 = 약 등록·복약 알림·복용/건너뜀/30분 뒤·잔여 개수·수동 보충·약 용도 한 줄 메모·기분 7단계 하루 1회·증상 빠른 기록·최근 2주 캘린더·앱 잠금·데이터 삭제·로컬 백업 내보내기. 이것만으로도 앱이 완결적으로 쓸모 있어야 한다(심사·별점).
  Pro = Apple Watch 앱 전체 · 약봉투 스캔/지난 처방 복사/일괄 등록 · 소진 예측과 진료일 기준 부족 알림 · 감정 단어·수면·꿈·활동 태그·증상 상세 · 기분일기 2층 · 약 알아보기/증상으로 약 찾기/약 모양으로 찾기 · 전체 기간 캘린더·검색·리포트·PDF·CSV · iCloud 동기화·대체 아이콘·테마.

- **2026-08-17 · Pro 유도는 딱 세 곳** (확정)

- **2026-08-17 · 기분 척도는 7단계 + 감정 단어** (확정)

  넘기기 가능. 존댓말, 판단·평가 없음. → `data/question_cards.json`

  3개 묶음(기분·불안 / 수면·에너지·인지 / 신체·부작용 의심). 공통 세기 0–10 + 항목별 보조 필드 1개(없음 / 시간 / 관련 약). 사용자 정의 항목도 동일하게 동작. → `data/symptom_catalog.json`

- **2026-08-17 · 약 DB는 식약처 공공데이터 번들** (확정)
  e약은요(효능효과·주의·이상반응 원문) + 낱알식별(모양·색·각인·저해상 이미지) + 의약품 허가정보. 공공누리 1유형, 앱 내 출처·기준일 표기. 정신건강 관련 성분 약 120종 × 상품명 약 600개를 오프라인 번들로. 약학정보원은 **앱 밖 외부 링크로만** 연결하고 내용을 복제하지 않는다.

- **2026-08-17 · 판단 기능은 넣지 않는다** (확정)
  용량 조절 권고·상호작용 판정·약 추천 없음. 원문 인용 + 출처 표기만. "증상으로 약 찾기"도 화면에 "검색 결과일 뿐 추천이 아님"을 명시. App Store 1.4.1 / 국내 의료기기 해당 여부 회피의 핵심.

- **2026-08-17 · 안전 카드** (확정)
  '자해·자살 생각'을 저장할 때, 또는 기분 '매우 힘듦(−3)'이 3일 연속일 때 표시. **109**(자살예방상담, 24시간) · **1577-0199**(정신건강위기상담) · 응급 112/119. 해외 로케일은 지역 번호. 닫기 가능하고 기록은 방해 없이 저장되며, 앱은 어떤 판단·진단·경고 문구도 붙이지 않는다.

- **2026-08-17 · 재고 = 사건의 합** (확정)
  잔여는 저장하지 않고 매번 다시 계산한다: **마지막 직접 정정 시점 이후 (보충 합 − 복용 합)**. 건너뜀·미기록은 차감하지 않음, 반쪽 복용은 0.25 단위 소수 허용. 예상 소진일 = 잔여 ÷ (하루 예정 개수 × 최근 4주 복약률). 부족 알림은 약별이 아니라 "다음 진료 전에 모자라는 약"으로 묶어 한 번. 이 계산은 순수 Swift 모듈로 분리해 단위 테스트 100%.

- **2026-08-17 · 앱 잠금은 기기 인증만 쓴다** (2026-08-20 뒤집힘 — 아래 참고)
  앱 전용 비밀번호·PIN을 만들지 않는다. `LAPolicy.deviceOwnerAuthentication` 하나로 Face ID · Touch ID 를 먼저 띄우고 안 되면 기기 암호로 떨어진다 → 사용자가 외울 것이 없고, 앱이 비밀값을 보관하지도 않는다. 무료 기능이며 기본은 꺼져 있다.
  **켤 때 먼저 한 번 인증한다** — 성공해야 켜진다. 잠금 방법이 없는 기기에서 켜져 사용자가 자기 기록에서 잠겨 나가는 것이 이 기능의 유일한 치명적 실패라서, 그 경로를 코드로 막았다(`canEvaluatePolicy` 가 false 면 잠금을 풀고 설정도 끈다).
  선택지 둘: "일기만 잠그기"(기록 탭만 잠그고 오늘·약·리포트는 열어 둠), "다시 잠그기"(바로 / 1분 후 / 5분 후, 기본 **바로**). 판단은 `JanjanCore/Security/LockPolicy.swift` 의 순수 함수가 하고 단위 테스트로 잠갔다. 나간 시각을 모르거나 시계가 거꾸로 갔으면 잠그는 쪽으로 기운다.

- **2026-08-18 · Pro 페이월과 게이팅 구현** (반영)
  StoreKit 2 하나로 끝낸다. 서버·영수증 검증 서버 없이 애플이 서명한 `Transaction.currentEntitlements` 만 진실로 보고, `.unverified` 는 세지 않는다. 구현 위치는 세 곳이다.

  | 무엇 | 어디 |
  | --- | --- |
  | Pro 경계·상품 ID·문구 | `Packages/JanjanCore/Sources/JanjanCore/Pro/ProFeature.swift` (순수 Swift, 단위 테스트 있음) |
  | 구독 상태 | `TheJanjan/Pro/ProStore.swift` |
  | 페이월 · 게이팅 | `TheJanjan/Pro/PaywallView.swift` · `TheJanjan/Pro/ProGate.swift` |

  상품 ID 는 `pro_monthly` · `pro_yearly`, 구독 그룹 이름은 `The잔잔 Pro`. 코드 어디에도 이 문자열을 직접 쓰지 않고 `ProProduct` 만 본다(체크리스트 3.4). 페이월에 적는 4줄은 `ProFeature.launchHighlights` 이고 ASC 구독 설명이 약속한 것과 같은 순서다.
  **가격을 코드에 적지 않는다** — "연 ₩19,900", "월 ₩1,658 꼴", 자동 갱신 고지 문장까지 전부 `product.displayPrice` / `price ÷ 12` + `priceFormatStyle` 로 만든다. 통화·지역이 바뀌어도 문장이 거짓이 되지 않는다. "7일 무료" 문구는 `Product.SubscriptionInfo.isEligibleForIntroOffer` 가 true 일 때만 나온다(3.1.2(b)).
  게이팅은 `.proGated(_:)` 한 줄. 무료 사용자에게 "Pro" 자물쇠 알약을 얹고, 누르면 원래 동작 대신 페이월이 올라온다 — 잠긴 기능이 반쯤 동작하는 경로를 만들지 않는다. 유도 지점은 설계대로 세 곳뿐이다: 설정 → Pro, 리포트 → PDF 내보내기, 약 추가 → 약봉투 스캔(워치 첫 실행은 워치 앱 붙일 때).
  스토어가 죽어도 앱은 멀쩡하다 — 상품이 비면 `storeUnavailable` 로 "지금은 스토어에 연결할 수 없어요. 무료 기능은 그대로 쓸 수 있어요." 를 보이고 크래시하지 않는다(3.6, 러비티에서 겪은 "상품을 찾을 수 없어요").
  시뮬레이터 확인용으로 `TheJanjan/Configuration/Janjan.storekit` 을 두고 XcodeGen 스킴의 `storeKitConfiguration` 에만 연결했다. 이 파일은 앱 번들에 들어가지 않고 아카이브·TestFlight 와도 무관하다. **StoreKit 2 구독에는 별도 entitlement 가 필요 없다** — In-App Purchase 는 모든 App ID 에 기본으로 켜져 있고, `com.apple.developer.in-app-payments` 는 Apple Pay 용이라 여기엔 넣지 않는다(entitlements 파일 그대로).
  디버그 전용 우회 `JANJAN_FORCE_PRO=1` 은 `#if DEBUG` 안에만 있고 릴리스에서는 컴파일 시점에 false 로 굳는다(6.5).

- **2026-08-20 · 화면을 저장소에 연결하면서 정한 것들** (반영)

  **계산은 화면 밖에 둔다.** 오늘 화면·워치 스냅샷·알림이 각자 스케줄을 훑으면 셋이 서로 다른 숫자를 말한다. 하루 계획을 `JanjanCore/Schedule/DayPlan.swift` 한 곳에서 만들고 셋 다 거기를 지난다. 재고와 같은 원칙이다 — 계획도 저장하지 않고 사건에서 매번 다시 만든다.

  **기록은 덮어쓴다.** 같은 날·같은 시간대·같은 약의 복용 기록은 새 줄을 만들지 않고 있던 줄을 고친다(`DoseRecorder`). 새 줄을 만들던 예전 코드에는 실제 버그가 있었다 — 알림에서 "복용함"을 누른 뒤 앱에서 "건너뜀"으로 고치면, 앞의 복용함이 남아 재고에서 계속 빠졌다. 하루 한 장인 체크인도 같은 이유로 `CheckInRecorder` 한 곳을 지난다.

  **늦게 답한 알림은 가장 가까운 예정분에 붙인다.** 23:50 취침약 알림에 00:05 에 답해도 어제 줄로 간다. `startOfDay(지금)` 을 쓰면 어제 줄은 영영 미기록으로 남고 오늘 줄에는 아직 오지도 않은 답이 적힌다. 하루 계획이 사건을 날짜에 붙일 때도 실제 복용 시각이 아니라 **예정 시각**을 본다.

  **알림은 요일마다 따로 만든다.** 시간대별로 요일을 합치면, 월요일만 먹는 약이 화요일 알림 문구에도 이름을 올린다. `DayPlan.weeklyReminders` 가 요일마다 그 날 실제로 먹는 약만 담아 준다. 알림은 바뀔 때마다 통째로 다시 깐다 — 무엇이 지워졌는지 따라다니며 하나씩 취소하려면 앱과 알림센터 두 곳에 같은 목록을 유지해야 하고, 그 둘은 반드시 어긋난다.

  키체인 항목은 `WhenUnlockedThisDeviceOnly` 라 **다른 기기로 따라가지 않는다.** 기기를 바꾸면 잠금이 꺼진 채로 시작한다. 일부러 그렇게 뒀다 — 따라가게 하면 새 기기에서 되찾을 길 없이 잠기는 경로가 생긴다. **저장된 항목이 있다는 것이 곧 잠금이 켜져 있다는 뜻이다.** 켜짐 여부를 UserDefaults 에 따로 두면 둘이 어긋나는 날이 오고, 그날 사용자는 열 수 없는 잠금 앞에 선다.
  틀리면 기다리게 한다: 5번까지는 벌 없이, 그다음 1분 · 5분 · 15분 · 최대 1시간. **영영 잠기지는 않는다** — 기다림은 반드시 끝나고 기기 인증은 기다리는 동안에도 열려 있다. 남은 횟수는 세어 보이지 않는다. 재촉이 되고, 곁에서 보는 사람에게 얼마나 더 눌러 볼 수 있는지 알려 주는 셈이 된다.
  쉬운 번호(0000 · 1234 · 1212 …)는 **막지 않고 한 번 알려만 준다.** 이 잠금이 막으려는 것은 곁에 있는 사람이 무심코 열어 보는 일이지 작정하고 만 번을 눌러 보는 사람이 아니다. 여기서 사용자와 싸우면 잠금을 아예 꺼 버리는 쪽으로 간다.
  기기 암호조차 없는 기기에서는 켜기 전에 "되찾을 길이 없다" 고 먼저 말한다. 08-17 결정은 그런 기기에서 잠금을 아예 못 켜게 막았지만, 이제는 알리고 사용자가 고르게 한다.

- **2026-09-01 · 어필 기획 셋 중 둘을 실행: "이번 달의 물결" 과 시리** (사용자 결정)
  귀여움(잔잔이 수달)·의미(물결)·편리(시리·NFC) 세 축을 목업과 함께 검토했고, 물결과 시리를 먼저 넣기로 했다. 잔잔이는 "떠 있는 것만으로는 모자라다" 는 피드백을 받아 보강 중이다.

  **시리** — "시리야, 더잔잔 약 먹었어" 로 화면 없이 적는다(`LogNearestDoseIntent` + `JanjanShortcuts`). 위젯과 고르는 규칙이 다르다: 위젯은 가장 이른 미답을 **보여 주고** 누르게 하지만, 시리는 화면이 없으므로 **지금 시각과 가장 가까운 미답**을 고른다(`DayPlan.nearestPending`, 테스트로 잠금) — 밤에 말했으면 방금 먹은 것은 취침 약이다. **대화문에 약 이름을 넣지 않는다.** 시리는 소리 내어 읽고, 옆에 사람이 있을 수 있다 — "잠금화면에서 약 이름 숨기기" 와 같은 철학. 출처에 `.siri` 를 더했다(문자열 고정, 테스트로 잠금).
  애플 정책 확인: App Intents/App Shortcuts 는 애플이 권장하는 공식 API 고, 심사 지침 1.4(의료)는 진단·처방 앱을 겨냥한다 — 우리는 기록만 하고 화면마다 고지가 있다. 문제 없음.
